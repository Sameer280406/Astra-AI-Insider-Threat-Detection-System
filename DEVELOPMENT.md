# Development guide

## Prerequisites and commands

Python 3.12; Node 22; pnpm 11; Docker Compose v2 for PostgreSQL/Redis. Install frontend with `pnpm install --frozen-lockfile`. Install backend into a virtual environment with `pip install -r requirements.txt`. See README for startup/environment commands.

Backend tests: `cd backend && .venv/bin/python -m pytest -q`.
Typecheck: `node node_modules/typescript/bin/tsc --noEmit` from project root.
Connected Next build: `NEXT_PUBLIC_DEMO_MODE=false NEXT_PUBLIC_API_BASE_URL= pnpm exec next build --webpack`.
Synthetic Site build: `pnpm run build` uses the existing Vinext build scripts; this is separate from the Docker Next build.

## Configuration rules

Do not commit `.env`, private keys, model tokens, database files, virtual environments or model weights. `.env.example` contains placeholders only. Only public API-base/demo-mode configuration is exposed to the browser. The Docker frontend uses same-origin Nginx routes; the API checks allowed Origin and requires an explicit mutation header.

For HTTPS production: `ENVIRONMENT=production`, `COOKIE_SECURE=true`, explicit HTTPS `ALLOWED_ORIGINS`, `ENABLE_DEMO=false`, non-placeholder secrets, PostgreSQL and Redis. Put TLS termination in front of Nginx. Do not expose PostgreSQL/Redis directly. Set resource limits and backups. Public organization onboarding currently creates starter tenants without email verification; gate or replace it before an internet production launch.

## Schema changes

Add Alembic migrations after 0003; never change an already-applied migration to retrofit deployed databases. RLS must cover each new business table. Snapshot/evidence models prohibit destructive downgrade. Keep migration credentials separate from runtime credentials. Revoke unnecessary grants on new tables after migration.

## Adding features

Use a strict DTO in `api/schemas.py` or a feature-specific schema file, a service, tenant repository access, permission dependency, and controller. Register frontend navigation in `lib/navigation.ts`. Shared UI is in `components/workspace-ui.tsx`; intelligence and containment have separate view modules. Do not call model endpoints from React.

The generic records table stores typed domain documents for this release. Plan migrations for indexed JSON fields/dedicated relational tables where query volume or integrity warrants it. Do not silently rename existing route fields.

## External adapters

`services/adapters.py` defines event queue/connector ports and HTTP normalization. Implement Kafka/Spark ingestion as a separately operated worker; use the same EventInput and authenticated tenant context. Do not mark Kafka/SIEM/SOAR connected merely after saving its URL.

`models/gateway.py` contains adapter registry and remote timeout/schema enforcement. See MODEL_INTEGRATION.

`services/response_adapters.py` contains mock endpoint/network and identity ports. Use a durable outbox before integrating real side effects; see CONTAINMENT_FORENSICS.

## Frontend demo boundary

`NEXT_PUBLIC_DEMO_MODE=true` selects `lib/client.ts`’s synthetic browser store. It never attempts to contact models. Browser changes are stored under `astra-demo-v2`. Reset through Settings. No browser-local storage property should be presented as a security control.

`NEXT_PUBLIC_DEMO_MODE=false` selects authenticated FastAPI calls and SSE. No fall-through to demo occurs on backend error. Docker uses this mode at build time. The demo includes exported synthetic records generated by `scripts/export-demo.py`; never use that script against production telemetry.

## API spec regeneration

With backend environment set, run Python from backend:

```python
import json
from app.main import app
open('../docs/openapi.json','w').write(json.dumps(app.openapi(),indent=2))
```

## Known boundaries

SSO is configuration-ready UI only; no OAuth callback/token exchange is implemented. User password reset, MFA, invitation delivery, service-account provisioning, configurable data-retention jobs and real payment collection are not implemented. The provider-neutral inference boundary and response policy flow are implemented and tested. Validate security, scale and provider behavior before live enterprise deployment.
